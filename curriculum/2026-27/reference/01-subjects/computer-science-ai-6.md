# Grade 6 Computer Science / AI — Syllabus + Teaching Guide

## Purpose
Build computational thinking, programming foundations, data literacy, and age-appropriate AI understanding through browser-based projects and explanation.

## Reference
Primary organizing reference: CSTA middle-school concepts/practices. AI lessons emphasize data, examples, models, evaluation, limitations, and responsible use.

## Year sequence
1. Problem solving, algorithms, sequencing, debugging
2. Conditionals, events, loops, variables
3. Scratch/browser programming projects
4. Web concepts and simple HTML/CSS when ready
5. Data representation and visualization
6. AI/ML foundations: examples, labels, features, training/testing, classification, confidence, error
7. Bias/limitations and responsible use
8. Capstone: define problem → design → build → test → revise → explain

## Current unit — algorithms and conditionals
Algorithm: a precise sequence of instructions.
Conditional: an instruction that chooses an action based on whether a condition is true or false.
Pattern: IF condition THEN action ELSE another action.

### Models
Thermostat: IF temperature > target THEN cool ELSE wait.
Plant monitor: IF soil is dry THEN water ELSE do not water.
Login: IF credential matches THEN allow access ELSE reject.

### Flowchart concepts
Start/end; input; decision; process/action; output; arrows showing sequence.

## Online activity: Scratch
Use https://scratch.mit.edu/ in a browser.
Suggested Grade 6 build: create a small interactive system where a sprite responds differently based on at least two conditions.
Example brief: a room-comfort controller. User changes temperature/humidity variables; sprite displays an action based on conditions.
Requirements:
- at least one variable;
- at least two conditional branches;
- visible output;
- test at least four input combinations;
- explain one bug or revision.

## Online AI mini-lab: Teachable Machine
Use https://teachablemachine.withgoogle.com/ when the lesson calls for classification.
Safe classroom version: use objects, drawings, or hand poses rather than personal identity.
Process:
1. Define two or three labels/classes.
2. Collect varied examples for each.
3. Train a simple model.
4. Test with new examples not used in training.
5. Record where it succeeds/fails.
6. Explain why more varied training examples may improve generalization.

## AI concepts
Training data: examples used to build/fit a model.
Label/class: category the model tries to identify.
Prediction: model output for a new input.
Confidence: model's numerical estimate, not proof that the prediction is correct.
Bias/coverage: unbalanced or narrow examples can produce poor performance on new cases.

## Project rubric
Problem definition 0–4
Algorithm/code correctness 0–4
Testing/debugging 0–4
Explanation/documentation 0–4
Iteration/independence 0–4

## Teaching rules
Have Atticus predict what code/model will do before running it. Ask him to explain why. Do not write the final project for him. Use hints and small code snippets only after he attempts the design. AI should be described as a computational system, not as magic or a human mind.
